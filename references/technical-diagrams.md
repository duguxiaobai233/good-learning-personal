# 教学技术图

本细则用于解释对象结构、连接关系和状态变化的专业图，不替代知识清单或课后总结的思维导图。按当前讲解内容决定是否配图，不要求每个知识点都画图，也不把绘图测试写入真实学习记录。

## 何时主动配图

当理解依赖“谁连接谁、信号往哪里走、对象处于哪里、操作前后发生什么变化”时，主动生成相应图，而不是等用户额外要求。原材料中的图若是理解概念或完成题目的必要条件，应保留清晰原图或忠实重绘；不能只引用页码。原图模糊、连线或符号无法辨认时，明确标出疑点，不凭空补全。仅为装饰或重复文字的图可以省略。

| 学习内容 | 优先图式 | 图中应表达的核心信息 |
|---|---|---|
| 自动控制系统、传递关系 | 系统结构图或方框图 | 信号方向、环节、求和符号、分支与反馈 |
| 信号流与梅森公式 | 信号流图 | 节点变量、有向支路及增益、回路与路径 |
| 栈、队列、链表、递归调用 | 状态快照、内存示意、调用栈 | 元素次序、指针含义、操作前后变化 |
| 算法执行、协议或事件顺序 | 流程图、时序图、状态转换图 | 条件、执行顺序、状态转移 |
| 力学、电路、几何关系 | 受力图、电路图、几何示意 | 方向、连接、参考系、已知量与约束 |
| 响应曲线、频域特性、实验数据 | 有坐标轴和单位的科学曲线 | 数据或函数、参数、范围与关键特征 |

图式随学科和任务变化；“堆栈”若可能指栈数据结构、调用栈或堆与栈内存，应结合上下文明确含义。不能用流程图替代需要准确空间位置的内存图，也不能把结构示意线当作实际计算的响应曲线。

## 先核对含义，再调整布局

画图前先列出对象、变量、连接和约束，并与正文使用同一套符号。来源图的重绘、根据给定关系生成的图和新编示意图应区分；来源页码用于核对，不代替解释。

- **控制框图：**框内是环节或传递函数，连线上是信号。求和点每条输入的正负号都要明确；取样点以实心点表示，交叉但不相连的线不能误画成取样点。逐段核对箭头、输入输出、反馈接入位置，以及扰动位于哪个环节前后。以节点关系检查闭环：例如负反馈应能读出 $e=r-Hy$、$y=Ge$；图与推导不一致时先修正，不能为匹配结论改符号。
- **信号流图：**节点表示信号变量，支路标签表示有符号增益；每个节点的方程应等于所有入支路贡献之和。核对平行支路、自环、反馈方向及负号；反馈支路上的 $-H$ 不能再次在节点处重复扣除。讲梅森公式时按有向图检查前向通路、回路和不接触回路；“不接触”指不共用节点，不由图上线条是否相交判断。
- **栈与其他状态图：**先约定栈顶位置、索引方向以及指针指向当前元素还是下一空位。每次 push/pop 后核对元素次序、栈顶位置、返回值和空满状态。将值、地址、索引、指针画成不同角色。若画调用栈，还应明确函数帧、局部变量和返回位置；不能把一般栈示意冒充某种机器的精确内存布局。

## 图要进入讲解和题目

图前说明它帮助回答的问题；图后解释符号、阅读顺序、关键关系，并将图上的一步与方程、程序或实际操作对应。讲等效变换、反馈化简或数据结构操作时，根据难点提供“变换前—关键步骤—变换后”的若干快照，保持节点名称与相对位置尽量稳定，并说明本步改变了什么、为何合法。无需把每条计算都画成一张图。

例题推理依赖的图应放在该题题干或相邻解析处；前面讲解已有的图可复用或只重绘必要局部，不让读者跨节找图才能理解当前推理。图较大时可在本题连续页面内分图，不强求整题压进一页。每个被引用的图应有可见、唯一的图号或本题分图标识及简短图题；复用图可标“例题4图(a)，据图6简化”，不要出现只有正文提到、图旁却找不到的编号。截取或单独交付例题时，一并带上其必要图示。

解释动作或状态变化时，图中实际呈现相关位置、方向与变化；只有“恢复平衡”等结论文字的方框不足以说明机制。按需要增加局部结构或前后状态，避免为满足配图数量而堆图。

独立练习必须附上解题所需的完整原始图和图例。题干图应给出必要条件，但不额外高亮正确路径、标出待求的等效增益、显示尚待计算的出栈结果，或预画关键化简步骤。讲解图和答案图可以展示这些内容；放在本题详细解析中，与原题题干分开。

## 复用已有工具并实际生成

现有课程 PDF 主线使用 **TikZ/PGF 与 XeLaTeX**：数学公式沿用正文 LaTeX，优先黑白清晰、可编辑的矢量图。参照[可运行示例](../examples/technical-diagrams.md)，在 Markdown 中使用 `tikz` 围栏，内容必须包含一个完整的 `\begin{tikzpicture}...\end{tikzpicture}`。渲染器已加载 `arrows.meta,positioning,calc,shapes.geometric,fit`；普通代码围栏仍按代码打印，不能靠更换围栏标签把任意代码变成图。

图块在正文原位排版、不浮动，仅在超出行宽时缩小。为保持字号可读，复杂图先拆成分图或减少无关标注，不把整张图无限缩小。图源应自包含：当前编译器只把生成的 TeX 复制到临时目录，不依赖外部图片、额外 `\input` 文件或 shell escape。一般节点与连线使用显式坐标或 positioning；不要在 XeLaTeX 路径使用需要 Lua 的 `graphdrawing` 自动布局库。

答疑中的单图可由 `render_study_pdf.py 输入.md 输出.tex --kind diagram` 生成无封面 TeX，再调用现有编译入口得到 PDF，渲染为 PNG 用于查看与展示。完整课程仍分别生成 day 的紧凑版与宽松版，并把图嵌入对应正文。保留 Markdown/TikZ 图源和必要预览，按原有目录规则保存。

**只有图代码不算完成交付。**答疑应直接展示实际图或 PNG；课程交付要确认图实际出现在两版 PDF 中，不能让用户自行运行代码才能看到图。

按任务需要可选用现成工具，但先检查本机可用性，不宣称已安装：Schemdraw 适合电路和信号处理元件图；Graphviz 适合树、链表和复杂拓扑；Mermaid 适合聊天中的简单流程。引入外部图时必须先解决当前自包含编译方式的集成限制，不能把一个文件路径写入 TeX 就宣称可重编译。科学曲线使用实际计算结果及标准绘图工具。技术图的连接、符号与数据需精确，不用生成式图片替代。

## 交付前检查

实际编译并渲染所有含图页面，目视检查箭头、正负号、下标、中文、标签重叠、连接误读和页边裁切；在最终页面大小下检查字号。再按上面的学科关系核对图与文字、公式或程序是否一致。两版课程都要查看，并逐一核对正文引用能否对应到本题附近的可见图号、图题和分图，检查分页是否把关键图与解析分离。编译成功并不代表图正确或可用于理解。若绘图或渲染失败，修复后重新检查；仍失败时说明具体未完成项，保留图源，不以未渲染代码冒充图。
