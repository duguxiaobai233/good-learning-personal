## 有些是默认安排或建议，不应扩大成绝对禁令

- “入门课程的每道核心例题原则上单独起页”里的“原则上”保留了按实际内容调整的空间。
- “考查可能性 × 分值或影响 × 薄弱程度 ÷ 时间”是排序思路，不是要求编造精确数值的计算公式。
- 导图要按内容关系选形式；参考文档中的“适合”“可采用”不等于所有导图必须固定模板。
- 原版没有规定所有学习都必须先做完整诊断，更没有规定零基础用户必须先做一套真题。
- 原版没有要求每次换聊天都重新报路径，也没有要求每次都提醒保存。它只是没有提供统一根目录和跨聊天寻找科目的具体规则。

这些判断是我对原文措辞的解释，不是另外增加的技能条款。

## 我实际新增和改写了什么

### 1. 安装时添加的本机环境适配

当前 SKILL.md 第 19—29 行的“本机运行环境（安装时配置）”整段是我添加的。它要求通过本机 `run-local.ps1` 入口调用原有三个 Python 脚本。

新增文件是 [LOCAL_SETUP.md](本机生效版/LOCAL_SETUP.md) 和 [scripts/run-local.ps1](本机生效版/scripts/run-local.ps1)。入口临时配置 Python、XeLaTeX 和中文字体路径，并转交给原来的生成脚本；它没有实现学习记录数据库或跨聊天监听。

作者要求 Python 3.10+、Pillow（PNG）、XeLaTeX 或 LuaLaTeX 等依赖；选择本机 Python 3.12.14、Pillow 12.3.0、MiKTeX 26.5 Portable、独立虚拟环境、CTAN 镜像和具体路径，是我的安装选择，不是作者锁定的版本或方案。

### 2. 你反馈“每次提醒太麻烦”后添加的保存与续学规则

当前 SKILL.md 第 8—17 行的“默认保存与跨聊天续学”整段是我添加的，具体包括：

- 固定默认根目录 `C:\Users\sora\Documents\Codex\学习记录`。
- 根目录的 `学习索引.md`、最近活动科目及科目目录的定位规则。
- 科目级 `源文件/学习进度.md`、每日 `源文件/学习记录.md` 的固定命名和字段约定。
- 每次使用技能时主动查索引、读取对应科目的计划和实际记录。
- 只说“继续学习”时优先接续最近科目；只有无法判断科目时才询问。
- 产生计划、授课、答疑或收到反馈等实质交互后，自动写记录并维护索引。
- 如当前聊天要求成品放在交付目录，主记录仍在默认目录，同时输出交付副本。

原版已经有“反馈后更新记录”和“跨天保留进度”。我补的是固定根目录、索引、固定进度文件名及跨聊天查找流程，不是从零创造了记录要求。

“日期变化、课程/PDF 生成不代表完成”也是我补充的具体表述，其原则来自原版的“未收到反馈保持待验证”，属于把已有证据要求写得更明确。

根索引的导出副本见 [学习索引.md](本机新增文件/学习索引.md)。当前只有空索引，没有正式科目或学习进度。

## 我之前回答中需要纠正或限定的说法

**“换聊天后需要重新提醒路径”不是原版要求。** 这是我当时在没有全局目录配置时给出的使用建议，讲得过于绝对。现在我已添加固定目录和主动查找规则。

**“换聊天直接说继续学习就会自动接着学”也不能作为无条件保证。** 目前实现是写给 agent 的持久指令，加上本地目录与索引约定。需要当次聊天实际选中或加载 Good Learning，并且能读写相同目录，才会照这些规则执行。改 description 有助于匹配续学请求，但它本身不能保证所有新聊天都会选中这个技能。

**“自动保存”是技能执行期间的约定，不是独立程序的后台监听。** 我没有新增监听所有聊天、应用关闭后继续运行或云同步的程序。原始三个脚本负责 Markdown→TeX、TeX→PDF、JSON→SVG/PNG；进度整理和索引维护由使用该技能的 agent 按指令完成。

**此前建议把当前聊天的学习资料放到 `outputs/<科目>`，来自本聊天环境对交付文件位置的要求及我的安排。** 作者原版反而要求同一科目的资料集中存放，不散落在通用输出目录。后来添加的“主记录＋交付副本”是我为兼顾统一学习目录与当前聊天交付位置写的适配，不是作者原文。
